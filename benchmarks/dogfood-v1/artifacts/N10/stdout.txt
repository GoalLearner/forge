## Conclusion: The defect has already been fixed

The user's report describes a real bug that existed in a prior revision, but it is **no longer reproducible in the current code**. Commit `7392a4b` ("fix: correct ledger confidence and attempt accounting") explicitly addressed this exact issue.

### Evidence

**The bug (prior behavior):** `src/session/ledger.ts:345-377` — `priceUsage()` used to inspect token-count provenance. When every count came back `reported` (which is DeepSeek's dialect — it states `prompt_cache_hit_tokens` and `prompt_cache_miss_tokens` outright), the cost was classified as `known`. An OpenAI-dialect provider would get `estimated` for the exact same spend. DeepSeek users saw an authoritative `$0.00` (no suffix) instead of `$0.00 estimated`.

**The fix (current code, `ledger.ts:365-377`):**
```typescript
// A previous revision promoted this to `known` when every count came back
// `reported` (DeepSeek states both halves of the cache split; the OpenAI
// dialect makes us subtract). But provenance of the token counts says nothing
// about the provenance of the DOLLARS: both dialects were multiplied by the
// same local models.json rates, so labelling one authoritative and the other
// an estimate distinguished two figures that are equally derived — and would
// present a stale price table as fact. `known` is reserved for a genuine
// provider-quoted amount, which no supported provider returns today.
return { state: 'estimated', nanos: partialNanos(usage, pricing), tokens };
```

All locally-calculated money is now `estimated`. The only warrant for `known` is `provenNoDispatch` (a call that never left the process), which is the one scenario where zero cost is a fact rather than an absence of data.

**Additional defects fixed in the same commit:**

1. **Billability assumption** (`loop.ts:222-253`): A dispatched request that returned no stream event (429, 5xx, reset socket) was treated as free. The line is now drawn at whether the outbound call was made — `dispatched=true` plus no observed usage yields `incomplete` ("Usage unavailable"), not `$0.00`.

2. **Exact-once recording** (`loop.ts:181-276`): Attempt finalization had no identity tracking, so a cancellation during retry backoff could produce duplicate ledger rows from both the retry callback and the catch block. Attempts now carry a stable key and a `finalized` flag.

**Verification — current behavior for DeepSeek V4 Flash with real usage:**
- 100 cache-miss input × $0.14 = 14,000 nanos
- 900 cache-hit input × $0.0028 = 2,520 nanos  
- 50 output × $0.28 = 14,000 nanos
- Total: 30,520 nanos → displays as `$0.00003 estimated`

The suffix `estimated` and the sub-cent precision make it unambiguously non-authoritative.
